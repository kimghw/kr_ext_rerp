# KR eClass + R&D ERP 현황 (Chrome 확장)

eClass 홈(`https://eclass.krs.co.kr/eClassVer4/Home/Index`)에 R&D ERP(`https://rnd.krs.co.kr`)의
**미승인내역(보완요청/신청)** 과 **과제별 카드미청구 내역**, HR System(`https://hr.krs.co.kr`) 급여명세서의 **기본연봉·올해 연구수당(직급별 한도·잔여)** 을 패널로 표시합니다.

## 설치 (압축해제된 확장 프로그램)

1. Chrome 주소창에 `chrome://extensions` 입력 → 우측 상단 **개발자 모드** 켜기
2. **압축해제된 확장 프로그램을 로드합니다** → 이 폴더(`E:\dev\kr_ext_rerp`) 선택
3. R&D ERP에 로그인된 상태(eClass에서 링크로 한 번 들어가 두면 됨)에서 eClass 홈을 열면 우측 상단에 패널이 뜹니다.
   - 로그인 세션이 없으면 패널에 "R&D ERP 로그인이 필요합니다"가 표시됩니다. R&D ERP 주소를 바로 열면 세션이 만들어지지 않으니, 처음에는 eClass 화면의 R&D ERP 메뉴를 클릭해서 로그인한 뒤 ↻를 누르세요.

카드미청구 / 과제집행비율은 제목 줄의 **미청구 / 집행비율** 칩이나 구역 제목의 스위치로 전환하며 마지막 선택이 기억됩니다. 책임자·과제 목록은 두 보기가 공통입니다.

**집행비율 계산**: 비목별 집행비율은 R&D ERP 자금현황과 같이 `승인액(B) ÷ 예산액(A)` 입니다.
과제 합계 집행비율은 여기에 **이 과제 카드의 미청구 사용액**(청구 전이라 아직 승인액에 잡히지 않은 금액)을 더해 `(승인액 합계 + 미청구액) ÷ 예산액 합계` 로 계산하고,
합계 예산잔액도 미청구액을 뺀 값으로 표시합니다. 같은 계좌를 쓰는 다른 과제와 공용인 거래는 어느 과제에도 넣지 않습니다.
표의 "미청구" 행은 비목이 정해지기 전이므로 예산 열은 비어 있고, 잔액 차감액과 예산 대비 비율만 표시합니다. 계산식은 합계 행과 집행비율 막대의 툴팁에서 볼 수 있습니다.
설정의 **과제집행비율 비목 선택**에서 조회된 모든 비목을 하나씩(또는 모두 선택/해제로) 포함·제외할 수 있으며, 제외한 비목은 합계·비율 계산과 표에서 모두 빠집니다.
아직 고르지 않은 비목은 이름에 인건비·연구수당·간접비가 들어가면 기본 제외, 그 외는 기본 포함입니다.

**예상 비용(계획)**: 펼친 표의 비목 이름 옆 **＋** 버튼을 누르면 그 비목 밑에 입력 줄이 열리고, **세목 · 수량 · 단가 · 금액**을 적어 추가(Enter)합니다.
수량 × 단가를 적으면 금액이 자동으로 채워지고, 금액을 직접 적으면 단가를 수량으로 나눠 맞춥니다 (수량을 비우면 1). 세목 칸에는 청구서 세목 빠른 선택 버튼의 표시이름과 이미 적어 둔 세목이 자동완성으로 나옵니다.
적어 둔 항목은 비목 밑에 `↳ 세목 · [−] 수량 [＋] × 단가 · −금액 · +예산 대비 비율`로 나열되고(수량 −/＋ 로 바로 증감, ✎ 수정, × 삭제), 그 비목과 합계에 **예상 반영** 행(예상 비용을 뺀 잔액, 더한 집행비율)이 추가되며, 접힌 과제 행의 잔액 밑에도 예상 잔액이 작게 표시됩니다.
입력 줄의 수량 칸에도 −/＋ 버튼(↑/↓ 키)이 있습니다.
**월간 구독**: 입력 줄의 **월간** 버튼을 켜면 수량 대신 **결제일**을 고르고 단가 칸이 월 결제액이 됩니다. 수량은 매월 그 날 결제로 보고 오늘(당일 포함)부터 올해 12월까지 남은 결제 횟수를 그릴 때마다 다시 세므로 날짜가 지나면 저절로 줄어듭니다
(예: 결제일 8월 2일이면 9월 2일까지는 9·10·11·12월의 4회, 9월 3일부터는 3회). 항목 줄에는 `월간 2일` 태그와 남은 횟수가 표시되고 −/＋ 버튼은 없습니다 (결제일을 바꾸려면 ✎ 수정). 31일처럼 짧은 달에 없는 날은 그 달 말일로 봅니다. 예상 항목이 있는 과제는 표 머리글 **비목** 옆에 눈 아이콘(감추기/보이기)과 저장 아이콘이 붙습니다.
예상 항목은 **기본으로 감춰져** 있어 표에는 ERP 값만 나오고 접힌 과제 행의 잔액 밑 **예상 잔액**만 보입니다. 눈 아이콘을 누르면 그 과제의 ＋ 버튼·항목 줄·예상 반영 행이 나타나고, 다시 누르면 감춥니다. 보이기 상태는 저장하지 않으므로 패널을 다시 열면 다시 감춰집니다 (항목이 없는 과제는 ＋ 버튼이 항상 보임).
항목은 입력·수정·삭제 때마다 확장 저장소(`chrome.storage.local`)에 자동 저장되어 브라우저를 다시 시작해도 남으며, 저장 아이콘은 지금 한 번 더 저장하고 "저장됨"을 잠깐 표시합니다 (툴팁에 저장 건수와 마지막 저장 시각).
설정에서 제외한 비목(예: 연구수당)에 예상 비용을 적으려면 먼저 **과제집행비율 비목 선택**에서 그 비목을 켜 표에 보이게 하세요. 표에서 사라진 비목에 남은 항목은 "표에 없는 비목" 묶음으로 보여 주고 합계의 예상 반영에는 넣습니다.
이 값은 R&D ERP 에 보내지 않고 확장 저장소(`chrome.storage.local`의 `plannedExpenses`, 이 브라우저 프로필)에만 저장되며, 툴바 팝업과 eClass 패널이 같은 값을 씁니다.

패널은 기본적으로 eClass 본문의 "Popup Notice" 카드 위에 삽입되며, 설정에서 우측 상단 띄우기로 바꿀 수 있습니다.
제목 줄(버튼 제외) 아무 곳이나 클릭하면 접고 펼 수 있으며, 접힘 상태는 기억됩니다.

툴바 아이콘 배지에는 **승인이 필요한 건수(보완요청 + 신청)** 가 있으면 그 수가 빨간색으로 우선 표시되고, 없으면 **카드미청구** 건수가 회색으로 표시됩니다(아이콘에 마우스를 올리면 항목별 건수). 아이콘을 누르면 같은 패널이 팝업으로 열립니다.

## 설정 (아이콘 우클릭 → 옵션, 또는 패널의 ⚙)

- **내 참여 과제만 보기**(기본 켜짐): 과제별 참여인력(`rtask_0008_t03_01_r001`, 참여구분 "계속")에 본인 학번/사번이 있는 과제만 남깁니다.
  사번은 R&D ERP 레이아웃(`rderp_layoutMain.act`)의 hidden 값 `MAND_USER_ID`(전역 `gUserId`)와 메인 프레임의 "OOO님, 안녕하세요." 문구에서 자동 감지하며, 설정에서 사번 또는 이름을 직접 입력할 수도 있습니다.
  사번이 참여인력 `EMP_NO`와 맞으면 사번만 씁니다. 이름으로만 대조할 때 같은 이름의 사번이 둘 이상(동명이인)이면 과제를 표시하지 않고 패널·설정 페이지에 후보(이름·사번·역할·과제)를 보여주며, 설정에서 본인 사번을 고르면 바로 다시 조회합니다.
  사번/이름을 모르면 다른 과제가 섞이지 않도록 과제를 표시하지 않습니다. 이때 R&D ERP 탭이 열려 있으면 확장이 브리지 스크립트를 그 탭에 직접 넣어(`scripting` 권한) 사용자 정보를 읽어 온 뒤 다시 판정하므로, 확장을 설치/재로드한 뒤 ERP 페이지를 다시 열 필요가 없습니다.
- **과제별 카드 귀속(계좌번호 규칙, 기본 켜짐)**: 과제카드발급내역의 카드 계좌번호가 그 과제 기본정보의 과제관리계좌(`rtask_0010_02_r003`)와 같은 카드만
  그 과제의 카드로 보고, 그 카드의 미청구 거래만 과제 밑에 표시합니다. 계좌가 다른 카드는 설정에서 과제별로 포함/제외를 재정의할 수 있습니다.
  어느 과제에도 귀속되지 않은 거래는 기본으로 숨기고, 설정의 "미귀속 카드 내역 표시"를 켜면 별도 묶음으로 보여줍니다.
- **과제 선택**: 조회된 과제 목록에서 체크를 바꾸면 바로 저장·적용되어, 해제한 과제는 카드 조회와 패널 표시에서 제외됩니다 (새 과제는 기본 포함).
- "과제별 카드 귀속", "모니터링 카드 선택", "카드 별명", "미승인내역 실시간 조회", "고급: 서비스 ID / 입력값" 구역은 제목을 클릭해 접고 펼 수 있으며(기본 접힘), 마지막 상태를 기억합니다.
  접힌 제목 옆에 과제·카드 수, 필터 모드, 미승인내역 서비스 설정 여부, 고급 설정 변경 여부가 요약으로 표시됩니다.
- **카드번호 필터**: 전체 보기 / 선택한 카드만 보기. 과제별 **과제카드발급내역**(`rtask_0008_t01_01_r002`)을 불러와
  체크한 카드만 모니터링합니다. 목록에 없는 카드는 뒷자리(4~8자리)로 직접 추가할 수 있습니다.
- **카드 별명**: 발급 카드 목록의 카드마다 별명을 적으면 패널의 카드별 보기·거래 행에서 카드번호 뒤 8자리 대신 별명을 보여줍니다 (뒷자리는 툴팁과 옆 글씨로 남음). 목록에 없는 카드는 "뒷자리=별명"으로 직접 입력. 입력하면 바로 저장·적용됩니다.
- **과제집행비율 비목 선택**(과제 선택 바로 아래): 선택한 과제의 자금현황에서 조회된 비목 목록에 체크 = 포함, 해제 = 계산·표에서 제외. 모두 선택/해제 버튼이 있고 체크를 바꾸면 바로 저장·적용됩니다.
  아직 목록에 없는 비목은 이름에 인건비·연구수당·간접비가 들어가면 기본 제외(설정값 `budgetExcludeDefault`), 그 외는 기본 포함입니다.
- **조회 옵션**: 사용일자 조회 범위(기본 6개월 전 ~ 1개월 후), 0건 과제 숨김(카드미청구 보기에만 적용), 캐시/자동 갱신 주기
- **청구서(카드) 입력 도우미**(기본 켜짐, 아래 참고): 예산(비목)·RCMS 사용금액구분 기본값, 세목 빠른 선택 버튼 목록, 첨부문서 드래그 앤 드롭을 켜고 끕니다.
- **급여·연구수당 (HR System)**(기본 켜짐, 아래 참고): 급여명세서 수집과 패널 표시, 직급(P1~P4, 비우면 HR 직원 정보에서 자동 감지)과 직급별 한도 비율(기본 P1 18% · P2 20% · P3 22% · P4 24%), 기본연봉·연구수당 항목명, HR 탭에서 지금 수집, 수집한 급여 정보 보기/지우기
- **미승인내역 실시간 조회**: 기본값이 메인화면과 같은 서비스(`rmain_0002_01_r006`, 아래 참고)라 별도 설정 없이 갱신 주기마다 자동 조회됩니다. 다른 서비스로 바꾸고 싶을 때만 수정
- **고급**: 서비스 ID / 입력 JSON (기본값은 R&D ERP 화면 스크립트에서 확인한 값)

## 청구서(카드) 입력 도우미

R&D ERP 청구서(카드) 화면에서 과제 지출내역(미청구 카드 행)을 골라 **청구내역** 폼이 뜨면 `content/rnd-claim.js`가 다음을 합니다 (설정 `claimHelper`).
화면 요소의 ID를 쓰지 않고 라벨 문구("예산", "RCMS 부가정보"/"사용금액구분", "첨부문서", "청구")로 행을 찾으므로 화면 구조가 바뀌면 동작하지 않을 수 있습니다.

- **기본값 채우기**: 예산(비목) 선택이 "선택"(비어 있음)이면 `연구활동비`, RCMS 부가정보의 사용금액구분이 비어 있으면 `본예산`을 고르고 `change` 이벤트를 보내 화면의 후속 처리(세목 목록·예산잔액 조회)를 그대로 타게 합니다.
  값이 비어 있을 때만 채우므로 이미 고른 값은 바꾸지 않으며, 다른 행을 골라 폼이 초기화되거나 "초기화"를 누르면 다시 채웁니다. 화면이 값을 계속 되돌리면(15초 안에 4번) 그 항목은 멈춥니다.
- **세목 빠른 선택**: "청구" 소제목 옆에 버튼(기본: 연구실 운영비, 회의비, 클라우드 사용비, 외부전문가 활용비, 소프트웨어 활용비, 연구활동비 기타비용)을 넣고,
  누르면 세목 목록에서 항목을 골라 줍니다. 비목이 비어 있으면 먼저 기본 비목을 고른 뒤 세목 목록이 채워지길(최대 5초) 기다립니다.
  항목명은 정확히 같음 → 포함 관계 → 2글자 조각 유사도 순으로 찾으므로 "클라우드 사용비"로 "클라우드컴퓨팅서비스 활용비"를 찾을 수 있습니다. 현재 고른 세목의 버튼은 파란색으로 표시됩니다.
  버튼 목록은 설정에서 한 줄에 하나씩 `표시이름=항목명=청구종류` 형식으로 바꿀 수 있습니다.
- **세목별 청구종류 기본값**: 버튼 목록의 셋째 값(기본: 회의비 → `17`, 외부전문가 활용비 → `83`)이 있으면, 세목이 그 항목으로 바뀔 때(버튼이든 직접 선택이든) 청구종류 라디오/select 에서
  `(83) …` 처럼 코드가 맞는 것(코드 대신 이름을 적으면 이름이 맞는 것)을 고릅니다. 화면이 세목에 따라 청구종류 목록을 다시 그리므로 최대 6초까지 기다립니다.
  세목이 바뀐 뒤에만 적용하므로 이미 저장된 청구서를 열었을 때의 청구종류는 건드리지 않고, 사용자가 라디오를 직접 바꾼 뒤에는 세목을 다시 바꾸기 전까지 다시 고르지 않습니다.
- **첨부문서 드래그 앤 드롭**: 첨부문서 행에 파일을 끌어다 놓으면 먼저 같은 출처의 프레임에서 `input[type=file]`을 찾아 넣고, 청구서처럼 파일 입력이 없고 "첨부" 버튼이 **파일등록 팝업**(`rcomm_0089_01.act`)을 여는 화면이면
  파일을 보관한 채 "첨부"를 눌러 팝업을 열고, 팝업에서 도는 같은 스크립트가 `BroadcastChannel`(같은 출처)로 파일을 받아 팝업의 파일 입력(없으면 "마우스로 파일을 끌어오세요" 구역에 합성 drop)에 넣은 뒤 **업로드** 버튼을 눌러 줍니다.
  업로드 직후 8초 동안은 MAIN world 훅(`rnd-hook.js`)이 `confirm()`을 자동 확인합니다. 팝업은 ERP 스스로 닫습니다. 팝업이 20초 안에 응답하지 않으면 안내만 표시합니다(그 창에 파일을 놓고 업로드를 누르면 됩니다).
  허용 확장자·용량·개수는 팝업 스크립트(`rcomm_0089_01.js`의 `changeFile()`)가 hidden 값 `APPR_FILE_CHK_YN`(Y=PDF·이미지만, I=이미지만, P=일부 이미지·500KB 이하), `GBCD_1_CD`(허용 확장자 목록), `MAX_FILE_SIZE`(MB), `MAX_CNT`, `SINGLE_YN`으로 검사하므로,
  팝업 쪽 스크립트가 같은 규칙을 먼저 적용해 걸리는 파일만 빼고 나머지를 넘깁니다(팝업 자체 검사는 걸리는 파일에서 alert 를 띄우고 그 뒤 파일을 모두 버립니다). 제외한 파일과 사유는 청구서 쪽 토스트에 표시합니다.
  청구서 쪽에서는 팝업이 무조건 거부하는 실행·스크립트 확장자(exe, bat, js, html 등)와 확장자 없는 파일만 미리 뺍니다. 목록에 올랐는지는 팝업 목록의 행 수(`filechkKey` 체크박스)로 확인합니다.
  ERP 프레임 안 다른 곳에 파일을 놓아도 브라우저가 파일을 열며 화면을 벗어나는 일이 없도록 기본 동작을 막습니다.
- 확장을 재로드하면 열려 있는 ERP 탭에도 스크립트를 다시 넣으며(`scripting` 권한), 다시 주입된 스크립트는 이전 것을 멈추고 넣었던 요소를 걷어낸 뒤 새로 붙입니다.

## 과제 참여율

미승인내역 아래 **과제 참여율** 줄은 본인의 계상률(참여율) 합계를 막대와 `NN% / 100%`로 보여주고, 클릭하면 과제별 표(책임자 / 과제명 / 역할 / 참여율 / 참여기간, 합계와 여유)가 펼쳐집니다. 과제명을 누르면 R&D ERP 과제정보 › 참여인력 탭(`TAB_ID=03`)이 열립니다.

- 출처는 "내 참여 과제만 보기"가 쓰는 과제별 참여인력 조회(`rtask_0008_t03_01_r001`)와 같고(12시간 캐시), 그 결과의 **계상률기준내역**(`INFO_REC`)에서 본인 행(사번이 맞는 과제가 하나라도 있으면 사번 기준, 아니면 이름 기준)의 `PART_RT`(계상률)를 씁니다.
  "내 참여 과제만 보기"를 끄면 표시할 과제(최대 조회 과제 수)에 대해서만 참여인력을 조회합니다. 사번/이름을 모르거나 동명이인이면 계산하지 않고 이유만 표시합니다.
- 같은 사람의 행이 종류별로 따로 옵니다(지급비목 `PAY_EXP_NM`/`MARK_EXP_NM`, 소득상세 `INCM_DIV_DTL_NM`, 소득구분 `INCM_DIV_NM`, 구분 `PART_HM_DIV_NM`). 종류에 **연구수당·기타소득·수당**이 들어가는 행은 참여율(인건비 계상률)이 아니므로 합계에서 빼고 ↳ 행에 "제외(연구수당)"로 표시합니다.
- 과제마다 **지급기간**(`PART_TRM_DT`, 예 `2026-04 ~ 2026-06`; 없으면 참여기간 `PART_TRM_DT_DTL`)에 오늘이 드는 계상률 행을 종류별로 **하나씩** 골라 더합니다 (종류가 다르면 재원별 행처럼 각각 참여율의 일부로 보고 합산).
  계상률기준내역은 계상률이 바뀔 때마다 행이 추가되는 화면이라 같은 종류의 현재 행이 여럿 겹치면 시작이 가장 늦은 행(같으면 뒤에 온 행)만 씁니다 (예: 4~6월 40%, 7~12월 55% 두 행이 있으면 9월엔 55%만).
  표의 기간 열은 참여기간이고, 계상률기준 행이 둘 이상인 과제는 원본 행을 `↳ 지급기간 · 종류 · 계상률 · 현재/종료/예정`으로 나열하며 합계에 넣은 행에 "반영"을 붙입니다. ↳ 행에 마우스를 올리면 그 행의 원본 필드(주민번호·계좌·연락처 제외)가 모두 보이니, 계산이 이상하면 이 값과 R&D ERP 참여인력 탭을 비교하세요. 아직 시작하지 않은 기간은 툴팁에 "이후 기간 계상률"로 보입니다.
- **계상률 체크제외**(`PARTRATE_YN=Y`) 행은 합계에서 빼고 표의 참여율 옆에 `+N%`로, 제목 옆에 "체크제외 N%"로 따로 보여줍니다. 계상률기준내역에 없고 인력기준내역(`HM_PER_REC`)에만 있는 과제는 참여율을 `-`로 표시하고 합계에 넣지 않습니다.

**예비 참여율(참여 계획)** (`lib/part.js`, `storage.local.plannedParticipation`): 펼친 표에서 참여기간 뒤 **＋** 를 누르면 그 줄 밑에 입력 줄이 열리고, **참여율(%)** 과 **기간**을 적어 추가(Enter)합니다. 기간 버튼을 누르면 **달력**이 뜨고 시작일 → 종료일 순서로 클릭합니다(시작일보다 앞 날짜를 고르면 시작일이 바뀜, 종료일을 비우면 미정). 달력 아래 **오늘부터 / 연말까지 / 과제 종료까지** 버튼으로 바로 채울 수도 있습니다.

- 저장된 계획은 그 과제 줄 밑에 `↳ 계획 · 시작 시 NN% · 참여율 · 기간` 줄로 나열되고(✎ 수정, × 삭제), "시작 시 NN%"는 계획 시작일 기준 **계획 반영 합계**(계획 기간에는 그 과제의 ERP 계상률 대신 계획 참여율로 보고, 그날 유효한 다른 과제의 계상률과 더한 값)입니다. 100%를 넘으면 빨간색.
- 오늘 계획 기간에 든 과제가 있으면 합계 밑에 **계획 반영** 합계 줄이 추가됩니다.
- ERP에 아직 없는 과제(신규·예정 과제)는 표 끝 **다른 과제 참여 계획 ＋** 로 과제명과 함께 적습니다(패널의 과제 목록에 있는 이름이면 그 과제로 연결). 이 계획은 그 기간 합계에 더해집니다.
- R&D ERP에는 저장하지 않고 이 브라우저(확장 저장소)에만 남습니다. 팝업과 eClass 패널에서 같은 목록을 씁니다.
- 합계가 90% 이상이면 막대가 주황, 100%를 넘으면 빨강과 "100% 초과"로 표시합니다.

## 급여·연구수당 (HR System 급여명세서)

HR System(`hr.krs.co.kr`)은 R&D ERP 와 다른 사이트입니다. HR 에 **로그인한 탭이 열려 있으면**(어느 화면이든, 급여명세서를 열 필요 없음) 그 탭의 `content/hr-pay.js`가
급여명세서 화면이 쓰는 API 를 `lib/hr-api.js`로 직접 호출해 확장 저장소(`storage.local.hrPay`)에 저장하고 백그라운드가 패널 캐시에 바로 반영합니다. HR System 에는 아무것도 쓰지 않습니다.

- **API** (급여명세서 화면 `/pay/payself/payself110/view` 의 인라인 스크립트에서 확인, 모두 GET, 추가 헤더·토큰 없음, 2026-09-23 기준):
  - 직원 정보 `/popup/psmst?emplNoName=사번&curCode=1&condition=&fieldFlag=emplNo` → `emplNo`, `emplNameHan`, `orgNameHan`, **`gradeCode`(직급, 예 `P2`)**. 검색어를 비우면 전 직원 목록(수 MB)이 오므로 반드시 사번으로 조회
  - 급여지급내역 `/pay/payself/payself110?baseYear=연도&emplNo=사번&transInd=Y` → `payDate`(지급일자) · `paySeqNo` · `payNameEnv`(내용) · `incomeAmt`(소득합계) … 본인 사번만 허용(다른 사번은 500)
  - 지급내역 `/pay/payself/payself110/income?payDate&paySeqNo&emplNo&transInd=&taxInd=&sortKey=` → `printNm`(소득명) · `incomeAmt` · `payCode` (기본연봉 `EPSL`, 연구수당지급 `AD91`)
  - 확장 출처(백그라운드·설정 페이지)에서 부르면 서버 CORS 필터가 `Origin: chrome-extension://…` 을 보고 **본문 없는 200**(`content-length: 0`)을 돌려주므로 HR 탭 안(콘텐츠 스크립트, 같은 출처)에서만 호출할 수 있습니다.
  - 로그인이 풀려 있으면 `/hrm_admin/login`(HTML)으로 리다이렉트됩니다 → `hrPay.status.loginRequired` 로 기록하고 패널·설정 페이지에 빨간 글씨로 안내
- **언제 수집하나**: HR 페이지 로드 때 한 번(최상위 프레임만; 저장된 값이 갱신 주기 안이면 건너뜀), 그 뒤엔 백그라운드가 R&D ERP 를 갱신할 때마다 열려 있는 HR 탭에 `hrCollect` 를 보내 함께 갱신합니다(같은 탭 연속 수집 최소 1분 간격). 설정 페이지의 **HR 탭에서 지금 수집** 버튼은 모든 달을 다시 읽습니다.
  사번은 HR 화면 좌측 프로필(`#_profile_userId`) → 저장된 `hrPay.empNo` → R&D ERP 사용자(`rndUser`) → 설정의 사번 순으로 정합니다.
- **읽는 것**: 올해 급여지급내역 목록 전체와, 아직 저장되지 않았거나 소득합계가 달라진 달의 지급내역(소득명 → 금액). 목록은 통째로 교체하고 목록에 없는 달은 지웁니다.
- **직급**: 직원 정보의 `gradeCode`(P1~P4)를 자동 감지해 기록합니다 (HR 화면에는 직급이 표시되지 않아 화면에서는 읽을 수 없음). 설정에서 직접 고르면 그 값을 우선합니다.
- **계산** (패널 `lib/render.js`):
  - 기본연봉(월) = 가장 최근 달 지급내역의 `기본연봉` 항목, 연 기본연봉 = 월 × 12
  - 올해 연구수당 = 올해 각 달 지급내역의 `연구수당지급` 합계 (툴팁에 달별 금액)
  - 연구수당 한도 = 연 기본연봉 × 직급 비율 (기본 P1 18% · P2 20% · P3 22% · P4 24%, 설정에서 변경)
  - 더 받을 수 있는 금액 = 한도 − 올해 지급 − **받기 예정 연구수당** 합계 (음수면 빨간색 "한도 초과"). 화면에는 이 금액과 받기 예정 목록만 보이고, 기본연봉·올해 지급(달별)·한도·직급은 금액 칸 툴팁에 있습니다.
  - 제목 옆 기간 = 올해 수집된 달의 첫 지급일 ~ 마지막 지급일과 급여 달 수. 올해 목록의 급여 달(내용에 "급여") 중 아직 읽지 못한 달은 "N월 급여 미수집"으로 빨갛게 표시 (목록을 모르면 1월부터 지난달까지 중 빠진 달)
- **받기 예정 연구수당**(`lib/pay.js`, `storage.local.plannedAllowance`): 펼친 구역 안 ＋ 로 메모·금액을 적어 두면 "더 받을 수 있는 금액"에서 빼서 보여줍니다.
  실제로 지급되어 급여명세서에 잡히면 × 로 지우세요. R&D ERP·HR 에는 저장되지 않고 이 브라우저(확장 저장소)에만 남으며, eClass 패널과 팝업이 같은 값을 공유합니다.
- 설정 페이지의 **급여·연구수당** 구역에서 수집된 원본(`hrPay`: 연도별 달 목록·지급내역, 직급, 사번, 마지막 수집 상태)을 확인하고 지울 수 있습니다.
- HR 급여명세서 화면은 RealGrid(가상 스크롤: 보이는 행만 DOM 에 있음)로 그려지고 `debugger` 기반 개발자도구 감지 스크립트가 있어, 화면(DOM)을 읽는 이전 방식(0.5.x)은 일부 달만 잡히고 직급은 잡히지 않았습니다.

## 미승인내역 실시간 조회

메인화면(`rmain_0002_01.act`)의 `setPendingStatusCount()`가 호출하는 서비스를 그대로 씁니다.

- 서비스 `rmain_0002_01_r006`, 입력 `{}` → `TEMP_SAVE_CNT`(임시저장), `SUPPLEMENT_CNT`(보완요청), `APPLY_CNT`(신청), `BUY_REQ_CNT`(구매요청). 조회기간은 서버가 최근 1개월로 고정
- 카드미청구·과제집행비율과 같은 주기(설정 "캐시 유지 / 자동 갱신 주기", 기본 10분, 최소 1분)로 백그라운드에서 갱신되며, 패널의 ↻ 로 즉시 갱신할 수 있습니다
- 서비스 호출이 실패하면(세션 만료 등) 마지막으로 메인화면을 방문했을 때 화면에서 읽은 값(방문 시각 표시)을 대신 보여줍니다
- 이전 버전에서 서비스 ID를 비워 둔 채 저장한 설정은 자동으로 기본 서비스로 바뀝니다
- 패널의 **신청** 건수를 클릭하면 전자결재 › 결재함 › **개인결재함**(`rappr_0002_01.act`, 결재대기함/결재완료함 탭)을 R&D ERP 레이아웃의 탭으로 엽니다.
  메뉴 ID는 사용자마다 다를 수 있어 `content/rnd-hook.js`가 로그인 사용자의 메뉴 트리(`comm_0001_01_r005`)에서 화면 URL → 메뉴 이름 순으로 찾고, 없으면 결재함 상단 메뉴(`menu_id_7`)를 클릭합니다.
  개인결재함 화면은 URL 파라미터를 받지 않아 탭·조회조건은 넘기지 않습니다. (MY신청함은 `rappr_0001_01.act`, 상급자결재함은 `rappr_0014_01.act`)

## R&D ERP 호출 규약 (분석 메모)

- `POST https://rnd.krs.co.kr/{서비스ID}.jct`, 본문 `_JSON_=encodeURIComponent(encodeURIComponent(JSON))`
- 응답 `application/json;charset=euc-kr`, `COMMON_HEAD.ERROR=true` 이면 오류. `CODE=GWM0001` 은 세션 없음(로그인 필요)
- 과제 목록: `rcomm_0009_01_r001` `{SEARCH_NM:"", SEARCH_GB:""(진행상태), GUBUN:"A", PRJ_AUTH:""}` → `REC[].PRJ_NO, ANL, PRJ_NM, PRJ_RSPR_EMP_NM, RCH_ST_DT, RCH_END_DT, PROG_STS_NM`
  (과제정보 화면의 과제책임자/과제명 검색 팝업 `rcomm_0009_01.act`와 동일)
